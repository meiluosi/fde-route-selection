# 速查表：常见场景与推荐起点

用于设计阶段快速定位技术路线。**这是起点假设，不是答案**：先过硬约束（见 [constraints.md](constraints.md)），再用客户样本验证（见 [model-bakeoff.md](model-bakeoff.md)）。

注：判断基于 2026 年 10 月的状况，请以最新官方文档为准。表中不出现具体模型名，模型归入哪个档位由带日期的记录说明。

## 一、场景 → 推荐做法

| 常见场景 | 推荐起点 | 升级或调整的信号 | 硬约束触发的变体 | 常见陷阱 |
|---|---|---|---|---|
| 文档字段抽取 | 中等能力模型 + 结构化输出约束 + 少量示例 | 版式多样导致漏抽且有标注 → 小模型或微调；扫描件、手写 → 先看识别与多模态环节 | 数据不出网 → 开放权重模型私有化，在更窄的池里重测基线 | 只测整齐样本；没有字段级评分；缺确定性校验层 |
| 企业知识问答 | 检索增强 + 引用标注 + 拒答机制 | 召回差 → 先改切分与检索，再考虑换模型；需要多跳推理 → 再升档 | 内网 → 本地向量库 + 私有化模型 | 用微调灌输知识；没有拒答导致编造；拒答只写在提示词里、没有逐模型实测（包括降级用的小模型）；知识库过期 |
| 长文档总结 | 分段处理 + 二次汇总，注意上下文长度上限 | 文档不长且稳定 → 直接放入长上下文；关键细节丢失 → 调整分段或先抽取再总结 | 同上 | 只评流畅度不核事实；上下文变长使成本和延迟上升 |
| 内容分类打标 | 小模型或微调模型，成本敏感场景优先 | 类别边界模糊、需要推理 → 升档；量大且有标注 → 微调或蒸馏 | 私有化小模型通常合适，但先测基线 | 类别体系没定稿就评测；标注一致性差 |
| 需要调用系统 | 工具调用 + 严格的权限与确认设计 | 调用不稳 → 缩小工具集、加校验、改成确定性工作流 | 工具接口须在客户环境内，权限与审计另行设计 | 给写权限而无确认；只测成功路径 |
| 强合规内网环境 | 开放权重模型私有化部署 + 本地向量库 | 在候选池内重测基线；能力不足时先评估检索、工作流、微调，而不是放松约束 | （本行即变体） | 把“私有化”当最高级路线；低估算力与运维成本 |

“强合规内网”是部署形态，不是适配手段，它与上面几行是叠加关系：先看任务选手段，再看约束定部署，见 [routes.md](routes.md) 的两条轴。

## 二、档位：不绑定具体型号

按部署方式和相对能力划分，不写参数量，也不写型号。型号如何归档由 [model-evidence/](model-evidence/index.md) 的带日期记录说明。

| 档位 | 含义 |
|---|---|
| 小型开放权重 | 可在较低算力上私有化，适合高并发、低延迟、窄任务 |
| 中型开放权重 | 需要较强算力私有化，通用任务的常见私有化起点 |
| 托管 API 中档 | 按调用计费，能力够用的常见默认 |
| 托管 API 旗舰 | 最强能力，成本和延迟最高，用于上限参照或确有必要的难任务 |

## 三、任务 → 起点档位

| 任务 | 起点档位 | 往下（更省）的信号 | 往上（更强）的信号 | 状态 |
|---|---|---|---|---|
| 字段抽取 | 中型或托管中档 | 版式固定、量大、延迟紧 → 小型或蒸馏 | 复杂版式、需要多模态 | 先验，待实测印证 |
| 分类打标 | 小型，或微调后的小型 | 类别清晰 | 边界模糊、需要推理 | 先验，待实测印证 |
| 知识问答（带检索） | 中型或托管中档 | 问题简单、知识库质量高 | 多跳推理、长上下文 | 先验，待实测印证 |
| 长文档总结 | 看上下文长度需求，不只看参数规模 | 分段后每段简单 | 必须一次性通读全文 | 先验，待实测印证 |
| 工具调用 | 中型及以上，关键是调用稳定性 | 工具集小、流程确定 | 步骤多、需要规划 | 先验，待实测印证 |

“先验”的含义：这些起点来自常见经验（如“绝大多数企业场景不需要最强模型”），没有在本仓库内被系统实测过。社区实测见 [model-evidence/index.md](model-evidence/index.md)，在客户场景里一律以客户样本实测为准。
