# 路线：适配手段与部署形态

路线有两条独立的轴，不要混成一条阶梯：

- **适配手段**：怎样让模型做好这个任务。
- **部署形态**：模型在哪里跑（见 [constraints.md](constraints.md)）。

“私有化 + 微调”不是更高一级的路线，而是两条轴上的一种组合。

## 适配手段

| 级别 | 手段 | 适合 | 主要风险 |
|---|---|---|---|
| 0 | 不用模型：规则、检索索引、传统软件 | 规则稳定、输入结构化、定义卡结论为 Non-AI | 规则维护成本、覆盖不足 |
| 1 | 提示词（含示例、结构化输出、术语表） | 任务清晰、知识通用 | 效果上限受限，对表述敏感 |
| 2 | 检索增强 / 长上下文 | 需要企业私有或经常变化的知识；知识量小且稳定时可直接放入上下文 | 依赖知识质量与检索效果；上下文变长会推高成本和延迟 |
| 3 | 工具调用 / 工作流编排 | 需要查系统、做计算、多步骤、分支判断 | 流程设计与失败处理复杂；每一步都是错误来源 |
| 4 | 微调（含蒸馏到小模型） | 有足够高质量标注、需要稳定的输出形式或术语；或大体量下压低成本、延迟 | 数据不足时反而变差；模型更新后要重做；需要可微调的模型 |

级别不是质量排名，也不是必须依次走完。

## 升级要有证据
升级的依据是**上一级在评测样本上的失败模式**，不是“更高级更好”。没有评测基线时，第一步是用最低成本的手段（通常是提示词）测出基线，同时承认“基线”要靠小样本、客户任务、事先写好的评分标准。

| 观察到的失败 | 先考虑 | 说明 |
|---|---|---|
| 输出格式或风格不稳 | 更严的提示词、示例、结构化输出 | 仍不稳且有大量标注时再考虑微调 |
| 缺企业私有或最新知识 | 检索 / 长上下文 | 微调擅长学形式，不擅长记住新事实，更新也困难 |
| 需要查询、计算、写入系统 | 工具调用 / 工作流 | 把确定性的部分交给代码 |
| 专业判断出错 | 先确认是缺知识、缺规则还是缺模型能力 | 缺知识→检索；缺规则→规则；都不是再看更强模型或微调 |
| 领域术语理解错 | 术语表入提示词、检索，再考虑微调 | 术语须经客户校准 |
| 质量够，成本或延迟超标 | 小模型、蒸馏、缓存、批处理 | 这是微调的另一类正当用途 |

上表是经验性的判断规则，不是定理；每次都要用本任务的失败样本核对。

## 什么时候可以跳级
须写明理由：
- 硬约束强制：例如必须私有化，则整条阶梯在更窄的模型池里重新测基线，而不是跳过。
- 体量决定：高并发、低延迟场景，先验证小模型或蒸馏的可行性。
- 已有评测证据：上一级的失败模式已清楚属于更高一级能解决的类型。
- 任务本身需要工作流（多步、调用系统），不是单次生成。

“绝大多数项目停在第二级”是经验说法，没有数据支持，不要当作事实引用；它的合理用途是提醒：升级前先确认上一级确实不够。

## 微调是最容易被误用的选项
客户常听说微调能“让模型学会我们的业务”，于是直接要求微调。判断时分开两类目的：
- **形式与风格、任务格式、术语用法、稳定性、蒸馏降本**：微调的适用范围。
- **记住新事实、持续更新的知识**：优先检索，微调用于灌输知识通常成本高、效果差、更新困难。

微调前提清单：高质量标注的数量与来源、与评测集隔离、标注一致性与分歧仲裁、可微调的模型及部署形态、模型升级后的重做成本、责任岗位。缺任何一项都写进决策卡的不确定性，不凭“有数据”三个字放行。

## 路线卡写什么
对每个候选路线写：适用条件、当前证据、数据前提、验证成本、运行成本、风险、责任、下一步。某条不适用也说明原因，不凑方案数量。
