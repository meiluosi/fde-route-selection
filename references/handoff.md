# 与 fde-problem-framing、fde-ramp 的衔接

两个上游 Skill 的版本指纹见 [upstream-sources.json](upstream-sources.json)。只记录接口与借鉴判断，不分发私有仓库全文。手动读取即可，无工具或仓库依赖；没有上游产物也能独立运行。

## 输入

| 上游产物 | 承接用途 | 本 Skill 新增 |
|---|---|---|
| fde-problem-framing 定义卡 | 场景、所针对的环节、成功指标、错误代价、拦截方式 | 把“要做什么”翻译成路线和模型约束 |
| problem-framing 的干预选择与结论 | 结论为 Non-AI 时直接承接 | 只核对规则/传统方案是否满足，不强行推 AI |
| problem-framing 的验证计划 | 已有的样本、标注与仲裁安排 | 沿用并补充模型比选所需的样本与记录字段 |
| ramp 的四个数字与人力单价（耗时、日频次、出错率、单次代价） | 日均量、每单人工成本、价值上限 | 推出每单可承受的 AI 成本 |
| ramp 的 glossary（已校准术语） | 提示词/检索里的术语表 | 只使用已校准的术语；“公开说法”标注来源 |
| ramp / problem-framing 的 sources、corrections | 来源与已修正判断 | 保留原 ID 与定位 |

给输入记录路径、版本/哈希和读取日期。多批输入同名 S01 时命名空间化，例如 ramp-a:S01，并保存映射，禁止覆盖原编号。未提供的文件标“未提供”，不模拟导入成功。导入仅在新的场景目录引用或复制必要片段，不改原件。

不继承上游的 AI 信号计数、四维评分作为选型放行规则，它们是候选线索而不是证据闸门；上游的成本上限也不等于能兑现的收益。行业平均数不替代客户的基线。

## 输出

交给后续阶段的是：
1. **选型决策卡**（[route-card.md](../templates/route-card.md)）：约束、路线、候选模型池、预算、结论与重开条件。
2. **评测需求**：要测什么任务、需要多少类样本、评分标准草案、护栏与失败样本要求。评测本身交给后续的评测/试点阶段，本 Skill 不执行。
3. **问题回流**：若选型中发现问题定义本身有疑问（例如预算上限显示价值不成立、错误代价与定义卡不一致），写成待确认事项回到 problem-framing，不在本 Skill 内悄悄改定义。
