# 与系列其他 Skill 的衔接

各 Skill 独立运行，通过手动读取的产物衔接，不互相依赖安装，也不修改它们的仓库。没有上游产物也能独立运行，缺的标“未提供”，不模拟导入成功。fde-problem-framing 与 fde-ramp 的 SKILL.md 版本指纹见 [upstream-sources.json](upstream-sources.json)；其余 Skill 只记录接口。

## 编号与结论词
跨 Skill 引用加前缀，保留原编号，不覆盖：`ramp:S01`、`framing:V2`、`kb:Q01`、`route:C3`。多批输入同名时命名空间化并保存映射。

本 Skill 内部编号：约束 `C#`，路线选项 `T#`，比选记录 `B#`。

结论词沿用 Proceed / Investigate / Non-AI / Stop-Defer。同名结论词含义随阶段不同，跨 Skill 引用时写 `route:Proceed`：

| 结论 | 在本 Skill 里的含义 |
|---|---|
| Proceed | 所写范围的下一阶段（进入候选模型实测、原型或试点配置），不是生产选型定稿 |
| Investigate | 硬约束、样本或基线证据不足，先做最小验证 |
| Non-AI | 规则或传统方案足以满足，承接 `framing:Non-AI` |
| Stop-Defer | 硬约束不可满足，或预算上限显示价值不成立；写重开条件 |

## 输入

| 上游 | 承接什么 | 本 Skill 新增 |
|---|---|---|
| fde-problem-framing 定义卡 | 场景、所针对的环节、成功指标、错误代价、拦截方式 | 把“要做什么”翻译成路线和模型约束 |
| framing 的干预选择与结论 | 结论为 Non-AI 时直接承接 | 只核对规则/传统方案是否满足，不强行推 AI |
| framing 的验证计划 | 已有的样本、标注与仲裁安排 | 沿用并补充模型比选所需的样本与记录字段 |
| ramp 的四个数字与人力单价（耗时、日频次、出错率、单次代价） | 日均量、每单人工成本、价值上限 | 推出每单可承受的 AI 成本 |
| ramp 的 glossary（已校准术语） | 提示词/检索里的术语表 | 只使用已校准的术语；“公开说法”标注来源 |
| ramp / framing 的 sources、corrections | 来源与已修正判断 | 保留原 ID 与定位 |
| fde-knowledge-base 的反馈 | 问题类型分布与不适合检索的比例；摸底发现的环境约束（如识别服务能否出环境）；改道路径是否需要生成查询语句的模型 | 据此调整路线与候选模型类型，补全约束清单 |

给输入记录路径、版本/哈希和读取日期。不继承上游的 AI 信号计数、四维评分作为选型放行规则，它们是候选线索而不是证据闸门；上游的成本上限也不等于能兑现的收益；行业平均数不替代客户的基线。

## 输出

| 下游 | 交什么 |
|---|---|
| fde-knowledge-base | 路线（含是否检索）、部署形态、硬约束（数据不出环境、私有化）、链路上各类模型的候选与约束（嵌入、重排、识别解析是否能出环境）。评测集与分层诊断由它负责 |
| fde-demo | Demo 所用模型与版本、部署形态、降级与兜底状态、已知局限；候选尚未实测时写明，不把 Demo 当成选型证据 |
| fde-pilot | 选型决策卡的重开条件、成本预算上限、模型版本与评测需求（样本类型、评分标准草案、护栏） |
| fde-comms | 对客户说“合规答复尚未取得”“成本超出预算上限”的事实依据，措辞与策略交 comms |
| fde-problem-framing（回写） | 预算上限显示价值不成立，或错误代价与定义卡不一致时，写成回写建议，不悄悄改定义 |

## 回写规则
下游发现上游假设被推翻，写成“回写建议”：对象产物、原内容、新证据（带前缀编号）、建议修订。由上游 Skill 的修订流程处理，不直接改原件。

## 在系列里的位置与边界
典型顺序：ramp → problem-framing → route-selection → knowledge-base（场景含文档检索时）→ demo → pilot，comms 贯穿各阶段。

| 事项 | 归谁 |
|---|---|
| 业务问题是否成立、该不该上 AI | framing |
| 模型比选、成本估算、部署与合规约束，包括嵌入、重排、识别解析模型 | 本 Skill |
| 文档摸底、知识治理、评测集、检索与生成的分层诊断 | knowledge-base |
| 评测的执行、试点方案与成效判定 | pilot |
| 对客户的措辞与沟通策略 | comms |

完整约定见 [fde-demo 的 series.md](https://github.com/meiluosi/fde-demo/blob/main/references/series.md)（私有仓库，链接需登录）。
